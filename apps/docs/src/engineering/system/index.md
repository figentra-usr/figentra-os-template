# Engineering system

"Engineering system" is the meta-layer: not what the rules are, but how work moves through them. This is where the roster of reviewers and agents, the gates a change must pass before merge, and the shape of the SDLC itself (spec → design → tasks → implementation → verification, or whatever this repo settles on) get documented.

It's written by whoever owns the delivery process — often the same person who configures CI and the repo's agent/skill setup — and it should track what's actually wired up (workflow files, hook configuration, required checks), not an idealized process nobody runs.

**Nothing has been written here yet.** Document the engineering system as it's built: which gates are required, which are advisory, and who or what enforces each one.
