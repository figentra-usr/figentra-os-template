# Compliance

Compliance documentation records the external rules the product must satisfy — data protection regulations, industry-specific requirements, audit obligations — and how the product meets them in practice. It is reference material for audits and due-diligence questions, and it should stay precise about what is actually true today rather than what is aspirational.

It's written by whoever owns compliance for the organization, often with input from engineering on how a given control is actually implemented, and it needs to be reviewed whenever the regulatory landscape or the product's own data handling changes.

**Nothing has been written here yet.** This is a blank template; add compliance documentation once there's a real regulatory scope to describe — for example once the product starts handling data subject to a specific regulation.
